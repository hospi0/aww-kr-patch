# Advanced World War ~千年帝国の興亡~ (Saturn JP, Rev B) — 초기 조사

작성 2026-07-20 / 세션 1

## 1. 입력 경계

- 원본: `C:\claude\roms\ss\Advanced World War - Sennen Teikoku no Koubou - Last of the Millennium (Japan) (Rev B) (22M)\`
- CUE + 24 BIN. **Track 01 = MODE1/2352 데이터(610,200,528 B = 259,439섹터)**, Track 02~24 = CD-DA.
- 제품코드 `GS-9087 V1.001 1997-05-21`, 볼륨 `ADVANCED_WORLD_WAR_SENNENTEIKOKU`.

- **모든 게임 데이터는 Track 01 하나에만 있다.** 오디오 트랙은 BGM 재생 전용.

## 2. 코드 모듈

루트의 확장자 없는 대형 파일(`0`, `GAME`, `SCHOOL`, `KOUGI`, `GMSELDT`, `INTERM`,
`SAKUSEN`, `KEKKA`, `MUSEUM`, `BADEND`, `END`, `STAFF`, `OPENTITL` …)은
**SH-2 빅엔디안 실행 오버레이**다. 선두가 `2f e6 2f d6 …`(`MOV.L R14,@-R15` 연속) 프롤로그.

`ALL.BIN`은 컨테이너: `u16 count(=0x11) + BE u32 오프셋 테이블`, 첫 오프셋 0x46 = 2+17×4 로 자기정합.

## 3. 폰트 (확정)

| 항목 | 값 |
|---|---|
| 글리프 크기 | 16×16 |
| 색심도 | **4bpp** (안티에일리어싱 있음) |
| 저장 배치 | 8×8 셀 4장, **TL → TR → BL → BR** 순, 셀당 4 B/행 × 8행 = 32 B |
| 글리프 크기 | **128 B** |
| 헤더 | 없음. 파일 선두가 곧 글리프 0 |
| 글리프 0 | 공백 |

### 폰트 파일과 인덱스 공간
| 파일 | 글리프 수 | ASC16CG와 동일 인덱스 |
|---|---|---|
| `ASC16CG` | 825 | (기준) |
| `ASCMSCG` | 830 | 820/825 = 99.4% — **같은 공간(상위집합)** |
| `ASCGSCG` | 594 | 240/594 — 0~239 공유, 이후 **독자 순서** |
| `ASCIMCG` | 697 | 240/697 — 위와 같음 |
| `ASC16CG2` | 320 | 0/320 — **완전 별개 세트** |

★ **인덱스 공간은 폰트 파일마다 다르다.** 0~239(ASCII·가나·기호·한자 16자)만 공통.
모듈이 어느 폰트를 쓰는지 확정하지 않고 한 매핑표를 전 모듈에 적용하면 안 된다.

## 4. 텍스트 인코딩 (확정)

- **BE 16비트 글리프 인덱스 배열.** Shift-JIS 아니고, SJIS→인덱스 변환표도 디스크에 없다
  (`82a082a282a4`(あいう), `8250825182528253`(０１２３) 전 파일 검색 0건).
- 제어코드
  | 값 | 의미 |
  |---|---|
  | `0xFFFF` | 레코드 끝 (확정) |
  | `0xFFFD` | 강제 줄바꿈 (확정 — 문장 중간에서 줄이 갈림) |
  | `0xFFFB`, `0xFFFE`, `0xFFF8` | 미해독. 레이블/선택지 프리픽스로 추정 |
- 검증: `설정`=`00e5 00e6`, `作戦`=`00ee 00ef` 검색이 텍스트 모듈에 집중.
  디코드 결과가 완전한 자연 일본어 (`선택한 무기는、FPW부족으로 사용할 수 없습니다。` 등).

### 매핑표
- `tools/charmap.py` = **ASC16CG/ASCMSCG용 825자 전수 판독 완료** (폰트 시트 육안 판독).
  - 0~62 ASCII / 63~223 가나 / 224~228 기호(`'`,`-`,`+`,`▶`,`ー`) / 229~824 한자·기호
  - 교차검증: `〈11c〉`=284=`。`, `〈108〉〈116〉`=武器, `〈109〉〈11f〉`=装備 — 문맥과 일치
  - ⚠️ 함정 2건 (이미 수정): 192~213은 `バビブベボ` 다음 `パピプペポ` 순 / 228은 글리프가
    긴 가로줄이지만 용례는 장음부호 `ー`
- `tools/derive_map.py` = 128바이트 완전일치로 타 폰트 표 자동 유도
  (ASCGSCG 494/594, ASCIMCG 542/697 유도. **잔여 100·155자는 육안 판독 필요**)

## 5. 텍스트 분량 (잠정)

`tools/findtext2.py`(0xFFFF 종료 + 가나밀도 필터) 기준 **고유 126,532자**.
단, **오탐이 남아 있다** — `/GE2`, `/INTERM` 상위 히트 일부는 그래픽/테이블 노이즈.
확실히 실텍스트로 육안 확인된 모듈:

| 모듈 | 성격 |
|---|---|
| `/SAKUSEN` | 작전 브리핑 (확인) |
| `/GMSELDT` | 게임 중 시스템 메시지·오류문 (확인) |
| `/GMDT`, `/KEKKA`, `/MUSEUM`, `/SCHOOL` | 데이터·결과·박물관·사관학교 |
| `/AM /BR /CO /GE /GE2 /IT /SO /FR /PO /FI …` | 국가별 시나리오 (동일 내용 중복 파일 다수) |

⚠️ `/KOUGI`(986 KB, 최대 모듈)는 v2 검출기에서 **레코드 0건**.
평문 텍스트가 아니거나 다른 종결 규약을 쓴다. **다음 세션 최우선 조사 대상.**

## 7. 한글화 관점 초기 판정

**유리한 조건이 크다.**
- 텍스트가 **글리프 인덱스**라 Shift-JIS 코드공간 제약이 전혀 없다. 새 인코딩을 뚫을 필요 없음.
- 한자 슬롯(ASC16CG 기준 약 596칸)이 한국어에는 전부 불필요 → **그대로 한글 음절로 재정의 가능**.
- 폰트가 4bpp AA 16×16 → 한글 가독성 확보에 유리.
- 폰트 파일에 헤더가 없어 글리프 교체가 단순(고정 128 B 슬롯).

**주의**
- 슬롯 수가 유한하다. 한국어 본문에 필요한 고유 음절이 596칸을 넘으면 폰트 파일 확장이 필요하고,
  그때는 로더·적재 버퍼 검증이 따라온다 (`references/strategy/runtime-assets.md`).
- 폰트별 인덱스 공간이 달라, 모듈마다 쓰는 폰트를 확정하기 전에는 일괄 재정의를 하면 안 된다.
